================================================================================
PROJECT DESCRIPTION
================================================================================
NexusAI is a specialized compliance engine designed for financial institutions,
particularly for banks. The system:

1. Accepts corporate policy PDFs as uploads
2. Processes and validates documents to ensure they are legitimate policy files
3. Extracts and chunks document content for efficient retrieval
4. Builds a vector database (Chroma) for semantic search
5. Uses ensemble retrieval methods to find relevant policy information
6. Answers user queries about policies using Google Gemini 2.5 Flash LLM
7. Provides a user-friendly Streamlit web interface

The engine is designed to help compliance teams and employees quickly find
and understand relevant policy information without manually searching through
hundreds of pages of documentation.

3. ingestion_service.py
   ─────────────────────────────────────────────────────────────────────────

   - setup_ocr(): Configures Tesseract OCR path for PDF processing
   - extract_pdf_elements(file_path): Extracts elements from PDF using

WORKFLOW & FEATURES
================================================================================

DOCUMENT INGESTION WORKFLOW:
─────────────────────────────────────────────────────────────────────────
1. User uploads PDF via Streamlit UI (Policy Upload tab)
2. File is saved to ./uploads/ folder
3. Document Classifier validates it's a policy (uses Gemini LLM)
4. PDF elements are extracted using unstructured library:
   - Text paragraphs
   - Tables with structure
   - Images
   - Metadata
5. Elements are chunked using title-based chunking strategy
6. Invalid chunks (noise, too short, garbage OCR) are filtered
7. Chunks are embedded using BAAI/bge-large-en-v1.5 model
8. Embeddings stored in local Chroma vector database
9. BM25 index created for keyword search

QUERY & RETRIEVAL WORKFLOW:
─────────────────────────────────────────────────────────────────────────
1. User enters question via "Ask Question" tab in UI
2. Query is processed through ensemble retriever:
   - BM25 retriever: keyword-based matching
   - Chroma retriever: semantic similarity search
   - Results combined and cross-encoded reranked
3. Top-K most relevant document chunks retrieved
4. Retrieved chunks formatted as context
5. Query + context passed to Google Gemini 2.5 Flash
6. LLM generates policy-aware answer
7. Answer displayed to user with relevant document references

KEY FEATURES:
─────────────────────────────────────────────────────────────────────────
✓ Smart document classification (policy detection)
✓ Advanced PDF extraction with table/image support
✓ OCR-aware chunking with noise filtering
✓ Hybrid retrieval (BM25 + semantic + reranking)

ADVANCED RETRIEVAL ARCHITECTURE
================================================================================

ENSEMBLE RETRIEVER SYSTEM:
──────────────────────────────────────────────────────────────────────────
The system uses a sophisticated multi-method retrieval approach:

1. BM25 RETRIEVER (Keyword-Based)
   - Traditional information retrieval
   - Good for exact term matching
   - Fast and efficient
   - Weight: 50%

2. SEMANTIC RETRIEVER (Chroma Vector DB)
   - Dense vector embeddings using BGE model
   - Captures semantic meaning
   - Handles paraphrasing and conceptual similarities
   - Weight: 50%

3. CROSS-ENCODER RERANKING
   - Takes results from both retrievers
   - Uses HuggingFace Cross-Encoder for precision ranking
   - Reorders results by relevance
   - Improves answer quality

RETRIEVAL FLOW:
   Query
     ↓
   ├─→ BM25 Retriever (Top-K results)
     ├─→ Vector DB Retriever (Top-K results)
       ↓
       ├─→ Combined Results
         ↓
         ├─→ Cross-Encoder Reranker
           ↓
           └─→ Final Ranked Results → LLM
